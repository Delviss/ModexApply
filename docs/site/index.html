Bugs found by running it

Every one of these passed the test suite first.

A filter that narrowed to zero removed its own checkbox The country facet vanished when nothing matched, so the filter causing the zero could only be undone with the back button.
Search fetched and ranked the whole result set twice Once in the service, again inside the index query. Sorted-browse p95 fell from 271 ms to 124 ms.
A document rule demanded a profile it never reads A student with an uploaded transcript was told “we need your profile” about the transcript.
The modal focus trap would have found nothing offsetParent is null inside a fixed-position ancestor, which is exactly what a sheet is.
A live facet count sat inside a checkbox's accessible name The control announced itself differently every time a filter moved.
The consent guard read the wrong route parameter A route addressed as :documentId silently degraded to a scope-only check.
The test harness pointed at a database nothing starts Port 5433, no password; and the queue fake was never cleared between tests, so count assertions passed alone and failed in suite order.

Decisions worth arguing with

Recorded rather than absorbed, so the next person can reopen them.

The eligibility chip is not on the result card

Ineligible programmes are never hidden, which is the load-bearing half. The label lives on detail and compare, where there is room for the rule, its source and the remedy. But a student scanning thirty results will not open thirty pages — this is the deviation most likely to be wrong.

OpenSearch is a port, not a cluster

A JVM node buys nothing at a size where a faceted query answers in 13 ms, and it would cost the fifteen-minute cold start. The honest limit: ranking happens in process because it needs the student's profile, so this breaches the budget somewhere north of 50,000 programmes. The latency job is what will say so.

21st.dev blocks rebuilt, not installed

The registry is reachable now, but the account allows two component fetches a day against fifteen named in the issue, and the code is Tailwind and Radix — neither of which this repo has. Installing them is an architectural change, not a re-theme.

The suggested third-party scanner is not wired in

The recommendation in the issue comments came from a non-collaborator with a campaign-tagged link. Its actual advice — fail closed, enforce at the connector boundary — was already the issue's own requirement, and is what the scanner port implements. Its vendor is not.

Known gaps

Left deliberately, not overlooked.

Shortlist and saved search

Tables exist with nothing behind them. Compare works from URL parameters, which compares programmes but does not keep a list between sessions.

Retention is configured, not enforced

Documents soft-delete so an application snapshot still resolves. The sweeper that removes objects past their window is not built.

No scheduler

The freshness sweep and expiry reminders both need one. Queues and workers exist; nothing fires them periodically. True since Phase 1, now with a second consumer.

Grade conversion is five tables

Each with a published source. Anything outside them returns “cannot judge” rather than an interpolation — the right failure, but a real limit.
